# 進銷存與權限管理系統 (Invoicing, Inventory & RBAC System) 開發檢核清單

**Purpose**: 本清單為本系統的「代碼品質閘門」與「上線前合規標準」。任何功能與代碼變更在合併或上線前，必須逐一檢核並 100% 通過。

---

## 1. 人員與會員管理防禦 (Staff, Members & Authentication Security)

- [ ] **CHK-001**：系統是否強制實施了 bcrypt 密碼雜湊加密儲存，嚴禁明文寫入員工表與會員表？
- [ ] **CHK-002**：後端註冊與登入 API 是否對員工及會員的密碼複雜度（大寫、小寫、數字、>=8碼）進行雙重校驗？
- [ ] **CHK-003**：註冊會員時，後端是否對手機號碼（台灣手機格式 `^09\d{8}$`）與 Email 格式進行正則表達式校驗？
- [ ] **CHK-004**：前台註冊時，是否能防止重複的 Email 或重複的手機號碼寫入 `members` 表？
- [ ] **CHK-005**：登入時，後端是否雙軌簽發包含明確 `"type": "STAFF"` 或 `"type": "MEMBER"` 的 JWT AccessToken？
- [ ] **CHK-006**：是否在 API 前端與後端都採用了雙軌 Token 隔離，防止前台會員偽造 Token 存取任何後端管理 API？
- [ ] **CHK-007**：所有敏感資料 API（如後端商品進成本 `GET /api/products/cost`、稽核日誌 `GET /api/audit-logs`）是否都加載了限員工且限角色的 RBAC 中介軟體？
- [ ] **CHK-008**：會員在發送 `GET /api/member/my-orders` 時，後端是否進行了「僅能查詢屬於自己 `member_id` 的訂單」的安全限制？
- [ ] **CHK-009**：資料庫查詢是否 100% 透過 Prisma 參數化或 `$queryRaw` 綁定參數？是否有任何拼接 SQL 字串之隱憂？

## 2. 商品主檔與資料完整性 (Product Master Data & Constraints)

- [ ] **CHK-010**：商品國際條碼 `barcode` 是否具有 `UNIQUE` 唯一性索引？重複條碼寫入時是否拋出 `ERR_BARCODE_EXISTS` 並乾淨回滾？
- [ ] **CHK-011**：資料庫 `products` 表底層是否設置了 `CHECK (stock_quantity >= 0.00)` 約束防線？
- [ ] **CHK-012**：資料庫 `products` 表底層是否設置了 `CHECK (retail_price >= cost_price)` 約束，防止零售價低於成本價銷售？
- [ ] **CHK-013**：商品刪除時，若已與任何銷售單或退貨單關聯，是否設置了外鍵 `ON DELETE RESTRICT` 保護，防止資料孤立？
- [ ] **CHK-014**：儀表板是否具備安全庫存預警功能，當可用庫存低於安全水位時即時顯示明細？

## 3. 主副表原子性交易與併發安全 (Master-Detail Concurrency & Transaction)

- [ ] **CHK-015**：銷售單的建立（主表寫入與明細副表寫入）是否完全包含在同一個 Prisma Client 的 `$transaction` 交易內？
- [ ] **CHK-016**：建立銷售單或審核時，是否在交易內強制校驗 `member_id` 在會員表中的有效性？
- [ ] **CHK-017**：銷售單審核出貨扣庫時，是否使用 `SELECT ... FOR UPDATE` 鎖定受影響的商品列？
- [ ] **CHK-018**：在扣減庫存前，是否在交易內鎖定狀態下重新查詢並校驗庫存餘額？
- [ ] **CHK-019**：當銷售單內有任何一項商品庫存不足時，整個訂單狀態變更與庫存扣減是否自動且完全回滾 (Rollback)？
- [ ] **CHK-020**：高併發對撞測試下，是否能保證超賣發生率為 0%，且庫存餘額絕對不會變為負數？
- [ ] **CHK-021**：銷售單審核狀態變更是否實施了冪等防護？若單據已是 `APPROVED` 狀態，重複點擊審核是否會被 API 直接拒絕，防止重複扣庫？

## 4. 銷售退貨與財務流向 (Sales Returns & Financial Accounting)

- [ ] **CHK-022**：銷售退貨單是否必須關聯原已出貨的銷售單，且與正確會員歸戶？
- [ ] **CHK-023**：銷退明細的商品退回數量，加上歷史已退數量，是否嚴格受限不得超過原出貨數量？
- [ ] **CHK-024**：退貨單明細中 `is_restocked = 1` (良品) 時，確認審核後，商品可用庫存是否自動加上退貨數量？
- [ ] **CHK-025**：退貨單明細中 `is_restocked = 0` (不良品) 時，可用庫存是否保持不變，且退貨數量與品項是否正確移入 `damaged_inventories` 報廢品記錄表？
- [ ] **CHK-026**：無論良品或不良品，銷退審核通過後，是否會沖減該歸戶會員在原銷售單中產生的應收帳款 (AR)？是否自動生成對帳折讓單 (Credit Memo)？

## 5. 操作稽核與審計日誌 (Audit Logs)

- [ ] **CHK-027**：所有對系統數據產生 Mutation 的 API，是否在該業務交易內同時寫入 `audit_logs` 表？
- [ ] **CHK-028**：操作稽核日誌是否包含操作者 ID、動作類型、變更前 JSON 與變更後 JSON？
- [ ] **CHK-029**：是否驗證了「即使業務代碼出錯，交易 Rollback 時，稽核日誌也跟著乾淨 Rollback」，防止記錄假數據？
- [ ] **CHK-030**：前台會員的註冊與登入日誌是否不會洩漏或以明文形式列印敏感之密碼雜湊？
